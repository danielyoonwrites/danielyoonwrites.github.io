# Fewer spam calls

Read `PROGRESS.md` first (where it stands and the next step), then `DECISIONS.md` (choices and their reasons) and `SPEC.md`.

A one-page guide at https://danielyoonwrites.github.io/fewer-spam-calls. The plan, the checked facts and the build steps are in `SPEC.md`. Keep its "Build plan" up to date.

## Rules for working here

- Same rules as the website's `CLAUDE.md`: plain words for a beginner, one small change per pull request with a check the owner does, no build tools, Moon jar design (in `.claude/rules/moon-jar.md`, which Claude Code loads by itself when working in this folder).
- Every fact on the page must come from an official source (FTC, FCC, the carrier, the phone maker, the State of California), checked when the page changes. Update the "Last checked" date and the sources list each time.
- If a fact can't be checked, leave it out or mark it, never guess. Menu paths on phones change often.
- Write for a grandparent: short sentences, no tech words, one action per line.
- Never ask for, send or store a phone number or any other personal information. No analytics or tracking.
