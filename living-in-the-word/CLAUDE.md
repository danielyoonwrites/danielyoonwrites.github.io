# Living in the Word

A little app that turns a Bible passage into discussion questions for a small group. It lives in this folder and is published at https://danielyoonwrites.github.io/living-in-the-word. Read `PROGRESS.md` first (where things stand and the next step), then search `DECISIONS.md` (choices and their reasons, oldest first; it's long) for anything the task touches, and read only the parts of `SPEC.md` the task needs (its sections are listed at the top). For anything about installing the app or app stores, read `STORE-PLAN.md`. Keep `SPEC.md`'s "Build plan" up to date. Every pull request updates `PROGRESS.md` and adds any new decision to `DECISIONS.md`.

## Rules for working here

- Same rules as the website's `CLAUDE.md`: plain words for a beginner, one small change per pull request with a check the owner does, no build tools, phone first.
- The app has its own look, "Paper and ink" (the owner's choice, October 26, 2026): clean like Kinfolk magazine, not the website's Moon jar design. Colors, fonts and layout are in `SPEC.md` ("The look") and at the top of `style.css`.
- The owner is a pastor and reviews every question before it's shared. Never share anything automatically.
- Be careful with Scripture: never invent a quote. The ESV text is on hold (no key; the owner may make the app paid someday, see `SPEC.md`). If it's turned on, the app shows the ESV text from Crossway's ESV API, under Crossway's rules (`SPEC.md`, "The Bible text"): no more than 500 verses or half a book at a time, never stored, never changed, always with "(ESV)", the copyright notice and a link to esv.org. The AI is never sent the ESV text. Before adding any other translation, check its usage rules.
- The AI writes 3 to 5 questions per passage (the owner's rule, October 26, 2026), in the order set in `server/worker.js` (`PATTERNS`), always the first and the last; the general questions in `app.js` are the fallback. There's no study method to choose: the owner removed them on October 26, 2026 (see `SPEC.md`). Don't add one back unless he asks. Mark anything that couldn't be checked.
- Stage 1 sends nothing anywhere. Save recent studies only in the browser (`localStorage`, key `living-in-the-word`). No accounts, analytics or tracking. The one exception is the server's daily-limit counts (`AI-PLAN.md`): a scrambled code for each connection, never an internet address, kept only for today and yesterday. Sign-ups (invite only, an email code or Google) follow `SIGNUP-PLAN.md` step by step; step S3, signing in with an email code and each person's own daily limit, is built (October 28, 2026), and step S4, the owner's page (October 29, 2026). The owner's page (`people`, `invite`, `turn-off` and `turn-on` in `server/worker.js`) answers only a phone signed in with the `OWNER_EMAIL` address, checked on every request, never with the passcode. Never send anything about a person to the AI. Sign-in codes and session keys are kept on the server only scrambled; the session key travels in the Authorization header, never in the web address.
- Only Bible passages reach the AI: the server checks every passage first (`looksLikePassage` in `server/worker.js`), so the AI can't be used for anything else. Keep its `BOOKS` list the same as `BOOKS` in `app.js`, and its `OTHER_NAMES` the same as `OTHER_NAMES` in `app.js` (used by `tidyPassage`, which writes a typed name out in full, like "Phil 2" to "Philippians 2"). Any new way of reaching the AI must go through the same check, the sign-in (or, until step S6, the passcode) and the daily limits.
- The owner's Bibles are the NASB, ESV and NIV, not the KJV (his choice, October 26, 2026). The passage picker's verse numbers follow them (`VERSES` and `IN_FOOTNOTES` in `app.js`; what was checked is in `SPEC.md`, "Choose from the Bible"). Keep `VERSES` in the same order as `BOOKS`, and never type verse counts from memory: take them from datasets that agree.
- Never put an AI key or any secret in this folder. The website is public, so anyone can read its code. The AI helper in stage 2 needs its own server; its plan is `AI-PLAN.md`. Server code may live in `server/`, never with a key in it.
- The page has a Content-Security-Policy (the `Content-Security-Policy` line near the top of `index.html`): it may only run its own script, use its own style sheet and Google's fonts, and talk to the AI helper's server. If you add any outside service (a script, a font, an image, a server), add it there too, or the browser blocks it. Never put text into the page as HTML (use `textContent`), and no inline scripts or `style="..."` attributes.
- Raise the `?v=` number on file links whenever a file changes.
- Screens change only through `show()` and `goBack()` in `app.js`; the Back list is `visited`. The back gesture stays in step with `visited` by itself when it changes in the same tap as a `show()` ("The back gesture" in `app.js`; `SPEC.md`). If `visited` ever changes anywhere else, call `matchBackGesture()` after it. Never add a history entry right after a back gesture: Chrome then skips it, and the next gesture closes the app.
- Works without reception: `sw.js` keeps a copy of the app on the phone (`SPEC.md`, "Works without reception"). If you add a file the app needs to open, add it to `APP_FILES` in `sw.js`. If the fonts link in `index.html` changes, change `FONTS` in `sw.js` too. It must never keep anything sent to or from the AI helper.
