## Limits of Claude's cloud sessions, and the workarounds that worked

- **Can't reach many websites directly** (Substack, Firebase docs, gstatic, Samsung, journal sites, PubMed, webkit.org, docs.github.com, danielyoonwrites.github.io itself). npm, GitHub and web search work.
- **GitHub's help pages:** read their source at `https://raw.githubusercontent.com/github/docs/main/content/...` (and `data/reusables/...` for the shared steps). This worked in October 2026.
- **Claude Code's docs** (code.claude.com) could be fetched with curl in October 2026.
- **Workaround for checking live pages or official sources:** run a temporary test on GitHub's computers. Replace `.github/workflows/publish.yml` on the Claude branch with a test-only workflow (`on: workflow_dispatch`, no publish job), push, trigger it with the GitHub tools on the branch, then read the job log. Put the real `publish.yml` back (`git checkout origin/main -- .github/workflows/publish.yml`) before opening a pull request. Test-only runs show green, so Dan doesn't see red X's.
- **Reading official pages from GitHub:** fetch them through Jina Reader, `https://r.jina.ai/<url>` with the header `X-Return-Format: text`, then grep for the key lines. Samsung's site blocks this.
- **In Auto mode** (October 26, 2026), Auto's safety check refused fetching a blocked page through `r.jina.ai` from the session, calling it a way around the network rules. Don't retry that or the GitHub workaround for it; use web search and mark the facts unverified, or ask Dan. webkit.org, bugs.webkit.org, developer.mozilla.org and firt.dev don't resolve from the session.
- **Substack** blocks GitHub's computers and Claude's sessions (Cloudflare "Just a moment"). Jina Reader gets through from GitHub, but answers 401 to visitors' browsers without a key.
- **Firebase emulator:** firebase-tools installs, but its CLI can't load rules here. Run the database emulator jar directly (details in `quiet-room/CLAUDE.md`).
- **Saved checks (October 29, 2026):** Living in the Word's checks are in `living-in-the-word/tests/` (the command is in its `PROGRESS.md`, "How to run and check it"). Add to them instead of writing new scripts.
- **Testing apps:** serve the repository with `python3 -m http.server 8765 --bind 127.0.0.1`, then drive it with Playwright at 360 pixels wide (a small Android phone) and 1280 (a computer), and take screenshots. Check what's actually visible on screen, not just the `hidden` setting: a button style once overrode `hidden`, and only a screenshot caught it. Stop the server with `fuser -k 8765/tcp` (a `pkill` that matches its own command line ends the shell).
- **Browser caching:** GitHub Pages lets browsers keep files for 10 minutes (`cache-control: max-age=600`). When a page's CSS or JavaScript changes, raise the `?v=` number on its links, or phones mix old and new files.
- **The stop hook** requires all changes to be committed and pushed before ending a turn.
- **Bible sites are blocked** by the session's network rule (the proxy answers 403): Bible Gateway, Bible Hub, esv.org, Wikipedia, biblestudytools.com and christianity.com, as of October 26, 2026. For verse data, attach public GitHub datasets with `add_repo` (read): `thiagobodruk/bible` (JSON for the KJV, NASB 2020, ESV, NIV and more; its verses aren't numbered, so line up neighboring verses to find a gap) and `scrollmapper/bible_databases` (large: clone with a blob filter and check out only the file you need). Web search works for confirming a verse's wording or footnote.
- **Also blocked (October 27 and 28, 2026):** support.google.com (Google Play's help), w3.org, resend.com (its docs) and docs.pwabuilder.com. Reachable: developer.apple.com (the App Review Guidelines and the Human Interface Guidelines, also as `.md` pages), developer.android.com, code.claude.com, and raw.githubusercontent.com for public repositories (PWABuilder's docs are in github.com/pwa-builder/pwabuilder, `docs/builder/`; Resend's request format is in github.com/resend/resend-node).
- **Testing the back gesture (October 28, 2026):** in Playwright with Chromium, open a DevTools session (`context.newCDPSession(page)`), go back with `Page.getNavigationHistory` and `Page.navigateToHistoryEntry` (a browser-side back, like Android's gesture), and turn on the `Audits` domain: an issue with the type "NavigationEntryMarkedSkippable" means Chrome would skip that entry and the next gesture would close the app.
- **Claude can write in `.claude/rules/`** (October 28, 2026), and Claude Code loads a rule file there by itself when a file its `paths:` list names is opened (checked live: opening `about.html` loaded both website rules). Claude still can't change `.claude/settings.json`.
- **Helpers working in parallel** (the Agent tool, October 28, 2026): give each one different files. The stop hook still asks for a commit before Claude's turn ends, even while helpers are writing: save a work-in-progress commit on the branch (no pull request is open, so nothing publishes).
- **Token cost of research (October 28, 2026):** eight helpers at Max effort, for the store research, reported about 2.3 million tokens between them. Use that only when Dan asks for it; High effort and fewer helpers for normal steps.
- **Store research (October 28, 2026):** support.google.com and play.google.com don't resolve at all, even through the WebFetch tool; developer.chrome.com, web.dev, webkit.org, support.apple.com and state legislature sites were blocked too. - **Testing the server and the app together (October 28, 2026):** load `server/worker.js` in Node as a module, with a stand-in for D1 built on Node's own SQLite (`node:sqlite`; run each batch as one transaction) and a replaced `fetch` for Resend and the AI. - **Testing install help (October 29, 2026):** headless Chromium never offers to install, so dispatch a stand-in `beforeinstallprompt` event with its own `prompt()` function; give each Playwright context an iPhone, Android or KakaoTalk user agent to check which steps show; fake `navigator.standalone` to test an iPhone that opened the app from its home screen.
- **Screenshots for Dan (October 29, 2026):** stand-in AI words show in the pictures, so make them fit the passage on screen and say they're stand-ins (a note about Philippians 3 on a Philippians 1 screen nearly went out).
- **Testing the owner's page (October 29, 2026):**
  - Launch Chromium with `proxy: { server: process.env.HTTPS_PROXY, bypass: '127.0.0.1,localhost' }` so Google's fonts load in screenshots. The browser already trusts the session's proxy.
  - `innerText` gives words the way CSS shows them (quiet buttons in capitals), so match them without caring about capitals.
  - A 400 or 403 answer shows in the console as "Failed to load resource": that's not a script error.
  - "Sign out" in a test really signs that key out on the stand-in server, so later steps need a fresh sign-in. The server allows 5 codes a day for one address.
  - Full-page screenshots draw the sticky top bar where the page was scrolled: scroll to the top first.
- **Cloudflare's docs (October 29, 2026):** developers.cloudflare.com doesn't connect from the session. Read their source instead: `git clone --depth 1 --filter=blob:none --sparse https://github.com/cloudflare/cloudflare-docs`, then `git sparse-checkout set src/content/docs/workers/ci-cd` (or the folder needed; the main branch is `production`).
- **Cloudflare's build results (October 29, 2026):** each build posts a check named "Workers Builds: living-in-the-word" on its commit. GitHub's check-runs list shows only the newest run of each name unless `?filter=all` is added (`https://api.github.com/repos/danielyoonwrites/danielyoonwrites.github.io/commits/<sha>/check-runs?filter=all`). That once hid a successful deploy behind a failed preview build of the same commit. Build logs are only in Dan's Cloudflare account: ask for a screenshot.
- **Checking `wrangler.jsonc` without deploying:** copy `worker.js` and `wrangler.jsonc` to the scratchpad and run `npx --yes wrangler@latest deploy --dry-run --outdir out` there (Wrangler 4.155.0 on October 29, 2026). It lists the bindings it would use.
