# Video editor

Read `PROGRESS.md` first (where it stands and the next step), then `DECISIONS.md` (choices and their reasons) and `SPEC.md`.

A simple video editor for the owner's own videos, on his Android phone in Chrome, planned November 2, 2026 (the name is the owner's choice). It does a few things well: a filter, lighting, text, clip order, crop, speed and better sound. It lives in this folder and is published at https://danielyoonwrites.github.io/video-editor (live since pull request 112; not listed in search engines; on the website's Projects page since pull request 138). Keep the "Build plan" in `SPEC.md` up to date.

## Rules for working here

- Same rules as the website's `CLAUDE.md`: plain words for a beginner, one small change per pull request with a check the owner does, no build tools, phone first.
- Just for the owner, on his Android phone in Chrome (his choice "A", November 2, 2026). Don't spend work on iPhones or other browsers unless he asks.
- The videos never leave the phone: the app reads them and makes the new file inside Chrome. No server, AI, analytics or tracking. The one planned exception is the owner's AI captions (`SPEC.md`, "AI captions, only for the owner"): only the sound of the trimmed clip, only to his own Cloudflare server, only when he taps "Make captions"; never the picture, and never for anyone else. Since build step 7a the server code exists (below), but captions are off for now (his "a," the evening of November 4, 2026, Pacific: "just to keep this simple"), so the page talks to no server.
- The captions server (build step 7a, November 4, 2026; off for now: not deployed, and `CAPTIONS.on` is `false` in `app.js`, which hides the passcode box even with `?owner`; to turn it back on, `PROGRESS.md`, "Turning captions back on"): `server/worker.js` and `server/wrangler.jsonc`, a Cloudflare Worker named `video-editor-captions` on the owner's Workers Free account, the same account as Living in the Word's, at https://video-editor-captions.danyoonsignup.workers.dev. Once he connects it, Cloudflare deploys it after each merge (Workers Builds): change its settings in `wrangler.jsonc`, never in the dashboard; only the secret `CAPTIONS_PASSCODE` lives there. It keeps nothing: logs off, never `console.log`, no database. It answers only `https://danielyoonwrites.github.io` with the owner's passcode. The free plan gives each request 10 ms of the server's own work, so the server never decodes the sound, and a piece is at most 700,000 letters of base64 (`MOST_SOUND`, about 16 seconds). Its address is in three places that must match: the name in `wrangler.jsonc`, `CAPTIONS.server` in `app.js`, and `connect-src` in `index.html`'s safety rule (`tests/server-test.mjs`, section S9, checks them). If a deploy ever breaks it, revert the pull request on GitHub (its "Revert" button) and merge the revert.
- No music button, nothing copyrighted, and no AI (the owner's words, November 2, 2026). One exception, chosen November 3, 2026: AI captions that only the owner can use, planned in `SPEC.md` ("AI captions, only for the owner") and built in the steps there (7a to 7c; off for now, his "a," the evening of November 4, 2026, Pacific). Build only what the plan says; ask him before changing it. No passcode, key or other secret ever goes in this folder: the repository is public, and the server's secret lives in Cloudflare.
- Never change or delete the owner's original videos: the app only reads them.
- Mediabunny reads and writes the video files. Its ready-made file is saved in `lib/`, with its license and a link to its source (its license, MPL-2.0, asks that people can find the source). Keep one version; update only on purpose, after reading its release notes, and say so in the pull request.
- Saving the finished video is the hard part. Claude's test browser (Chromium in the cloud session) can't make AAC sound without the add-on, can't read HEVC and can't share (checked November 2, 2026), and it has no video chip, so every pull request that changes saving has a check on the owner's phone.
- Screenshots and checks use made-up test videos, never the owner's own videos, and never his kids (the privacy rule in the root `CLAUDE.md`).
- The app writes each new video fresh (Mediabunny's `Output` with `CanvasSource` and `AudioBufferSource`, in `makeVideo()`), so none of the original's tags come along; they can include where a video was filmed. Anything that copies with Mediabunny's `Conversion` (the phone test) passes `tags: {}` (or only tags chosen on purpose): `Conversion` copies the original's tags unless told not to.
- Speed: the sound follows the speed like a tape (the owner's "b", November 2, 2026). The new video's sound is played at the speed in an `OfflineAudioContext` (`soundAtSpeed()`), and the playing video has `preservesPitch` off so it sounds the same. Change the two together.
- Better sound (the owner's "B", November 3, 2026): three switches and a Volume slider on the Sound tab. `buildSoundSteps()` in `app.js` makes the same steps for the playing video (from the first change on the Sound tab) and for the new video's sound, so they sound the same. With nothing changed, the sound passes through untouched. Each compressor there holds the sound back 6 thousandths of a second: if you add or remove one, change `soundDelay()` too. A high-pass or low-pass filter's Q is in decibels in Chrome (−3.01 is the smooth shape). Check any change with the saved checks, section J, which measure each step with test tones.
- The AAC add-on (`lib/mediabunny-aac-encoder.min.js`) contains FFmpeg under the LGPL: keep `lib/licenses/ffmpeg/` and the links in `lib/README.md` with it.
- Each page has a safety rule (a Content-Security-Policy, near the top): its own scripts and styles only, plus `'wasm-unsafe-eval'` and `worker-src blob:` for the AAC add-on, and, only while captions are on, `connect-src` for the captions server on the app page (captions are off for now, so it has none). Put words into the page with `textContent`, never as HTML, and no inline scripts or `style="..."` attributes.
- Every video must fit Instagram's, TikTok's and YouTube Shorts' upload rules (the owner's request, November 2, 2026). The `OUTPUT` settings at the top of `app.js` and `checkReady()` keep it so; before changing them, read `SPEC.md`, "Made for Instagram, TikTok and YouTube Shorts," and check the rules again.
- The look is dark (the owner's choice): its colors are at the top of `style.css`, and the checks test their contrast.
- The looks are Korean styles (the owner's choice, November 2, 2026), listed in `FILTERS` in `app.js`; the Korean ones are SVG filters near the top of `index.html`. The same filter goes on the playing video and on each frame of the new file, so they match. Draw frames on a normal canvas, never an OffscreenCanvas, which ignores SVG filters. The glow's blur is a share of the picture's width (`setGlowFor()`). Check any change to a look with the looks sheet and the saved checks (section H).
- The Edit screen's tabs (Dan's request, November 5, 2026): bordered buttons all the same width (`grid-auto-columns` in `.tabs` in `style.css`), in a row that slides left and right with about three and a half showing on a phone; `keepTabInView()` in `app.js` slides the row to show the chosen tab, from `selectTab()` and `show('look')`. Check any change with the saved checks, section M.
- Screens change only through `goDeeper()`, `show()` and `followHistory()` in `app.js`, so the phone's Back button (<) goes back one screen at a time; Back while a video is being made stops it.
- Run the saved checks after any change, and add checks for new work, from the repository folder: `node video-editor/tests/app-test.mjs` (the app; section L checks that the real page, with captions off, shows nothing and talks to no server, then tests the passcode box with captions switched on inside the test browser only, with the server's own code and a stand-in AI) and `node video-editor/tests/phone-test.mjs` (the phone test), and after any change to `server/`, `node video-editor/tests/server-test.mjs` (the captions server, with a stand-in AI). All must end "0 failed".
- Raise the `?v=` number on file links whenever a file changes.
- Text (the owner's "A", November 3, 2026): one line per video. `drawText()` in `app.js` draws it the same way on the playing video's text layer (a see-through canvas put over the picture) and on each frame of the new video, after the look; it switches the look and the lighting off for the words and puts them back. All its sizes are shares of the picture (`TEXT_LOOK`), and `textLines()` breaks the lines at one fixed size, so the preview and the video match. Check any change with the saved checks, section K.
- It's on the website's Projects page (`projects.html`, since pull request 138): a short line, a small "What I set out to learn" line (since pull request 142, when Dan put it first), a gray line saying it's made for an Android phone in Chrome, and a "How I built it" note, in the website's voice (`.claude/rules/website.md`). The line says only what works today. When what the app can do changes (shape and crop, several clips, AI captions), update both in the same pull request.
